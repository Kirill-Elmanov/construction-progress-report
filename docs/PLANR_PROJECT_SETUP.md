# Подключение нового проекта PLAN-R через Postman

## Что нужно заполнить в RostReport

Для каждого проекта нужны три значения:

1. **EPS ID актуальной версии графика** — уникален для проекта и версии графика.
2. **UUID «Целевой старт»** — определяется по справочнику атрибутов вашего пространства PLAN-R.
3. **UUID «Целевой финиш»** — определяется по тому же справочнику.

В пределах одного пространства UUID целевых дат обычно одинаковы для разных
проектов, но перед первым подключением их необходимо проверить.

## 1. Настройка окружения Postman

Создайте или откройте окружение `PLAN-R` и добавьте переменные:

| Переменная | Значение |
|---|---|
| `base` | `https://plan-r.example.com` |
| `token` | действующий пользовательский API-токен |
| `tenant` | UUID вашего пространства |
| `version` | версия API вашего экземпляра |

Порт `:81` добавлять не нужно: он относится к административному интерфейсу,
а публичный API работает по обычному HTTPS.

Для каждого запроса включите галочками следующие заголовки:

| Header | Value |
|---|---|
| `Authorization` | `{{token}}` |
| `x-tenant-id` | `{{tenant}}` |
| `x-version` | `{{version}}` |
| `accept` | `application/json;odata.metadata=minimal;odata.streaming=true` |

В `Authorization` передаётся только токен — слово `Bearer` не добавляется.
VPN к России должен быть включён во время запросов к PLAN-R.

## 2. Получение EPS ID актуального графика

Создайте запрос:

```text
GET {{base}}/public-api/eps
```

На вкладке **Params** добавьте:

| Key | Value |
|---|---|
| `filter` | `type eq 'version'` |
| `$top` | `100` |
| `$skip` | `0` |

Нажмите **Send**. В JSON найдите по названию нужный график и версию с названием
`Актуальная` (например, `СМР_Проект актуальный`). Скопируйте поле `id`
именно у записи с `type: "version"`. Это и есть EPS ID для карточки проекта.

Если нужной версии нет на первой странице, последовательно меняйте `$skip` на
`100`, `200`, `300` и повторяйте запрос. Остановитесь, когда ответ содержит
меньше 100 записей.

Не используйте ID записи с типом `project` или `schedule`.

## 3. Проверка найденного EPS ID

Создайте запрос:

```text
GET {{base}}/public-api/wbs
```

На вкладке **Params** добавьте:

| Key | Value |
|---|---|
| `epsId` | найденный EPS ID |
| `$top` | `1` |
| `$skip` | `0` |

Ответ `200 OK` с одной работой означает, что выбрана существующая непустая
версия графика. Если пришёл пустой массив, проверьте другую актуальную версию.

## 4. Проверка дат на конкретном блоке

Выберите в интерфейсе PLAN-R сводную строку, для которой видны шифр и даты,
например `S1570`, затем выполните:

```text
GET {{base}}/public-api/wbs
```

Параметры:

| Key | Value |
|---|---|
| `epsId` | EPS ID проекта |
| `filter` | `code eq 'S1570'` |
| `attributeIds` | UUID текущего старта |
| `attributeIds` | UUID текущего финиша |
| `attributeIds` | UUID целевого старта |
| `attributeIds` | UUID целевого финиша |
| `attributeIds` | UUID расчётного выполнения |
| `$top` | `1` |

Повторяющиеся строки `attributeIds` — это нормально. Они запрашивают:

- текущий старт;
- текущий финиш;
- целевой старт;
- целевой финиш;
- «Выполнение (%) расчёт».

Значения дат приходят в миллисекундах Unix Epoch. Для удобной проверки откройте
вкладку **Scripts → Post-response** и вставьте:

```javascript
const payload = pm.response.json();
const rows = Array.isArray(payload) ? payload : (payload.value || []);
const row = rows[0];

const fields = {
  start: "<CURRENT_START_ATTRIBUTE_UUID>",
  finish: "<CURRENT_FINISH_ATTRIBUTE_UUID>",
  targetStart: "<TARGET_START_ATTRIBUTE_UUID>",
  targetFinish: "<TARGET_FINISH_ATTRIBUTE_UUID>",
  percentDone: "<PERCENT_DONE_ATTRIBUTE_UUID>",
};

const result = Object.entries(fields).map(([name, id]) => {
  const value = row?.values?.[id] ?? null;
  return {
    field: name,
    uuid: id,
    raw: value,
    date: name === "percentDone" || value == null
      ? ""
      : new Date(Number(value)).toLocaleDateString("ru-RU"),
  };
});

console.table(result);
```

После повторного **Send** откройте **View → Show Postman Console**. Даты в таблице
должны совпасть с датами выбранной строки в PLAN-R.

## 5. Добавление проекта в RostReport

Откройте карточку созданного проекта под супер-администратором и заполните:

- `EPS ID актуальной версии графика PLAN-R` — найденный ID версии;
- `UUID атрибута «Целевой старт»` — UUID из справочника вашего пространства;
- `UUID атрибута «Целевой финиш»` — UUID из того же справочника.

Сохраните проект, откройте раздел с S-кривой и один раз нажмите
**«Актуализировать данные»**.

## Если проект находится в другом пространстве PLAN-R

В новом пространстве сначала запросите его справочник:

```text
GET {{base}}/public-api/wbs-attributes?epsId=<ID пространства>&$top=100&$skip=0
```

Повторите запрос с `$skip=100`, если первая страница содержит 100 записей.
Найдите атрибуты по `label` и используйте их поля `id`. Если вычисляемый
«Целевой финиш» отсутствует в справочнике, его UUID нужно запросить у
администратора PLAN-R или определить по ответу тестовой строки, дата которой
заранее известна из интерфейса.

## Экономия лимитов API

- Для поиска EPS запрашивайте только страницы по 100 записей.
- Для проверки проекта используйте `$top=1` и фильтр по известному шифру.
- Не выгружайте весь WBS вручную: RostReport делает это постранично,
  кэширует ответ и защищает повторные одновременные запросы.
- Не нажимайте «Актуализировать данные» несколько раз подряд.
